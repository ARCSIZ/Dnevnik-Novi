# 📦 Папка Data — хранилище всех данных «Колледж·ID»

Здесь находятся исходники слоя данных. На обычном сервере здесь же живёт база.
На **Bothost** постоянный диск монтируется как `/app/data` (нижний регистр),
поэтому `server.js` автоматически хранит runtime-базу там. Для переноса с
Bothost нужно скачать папку `data` через файловый менеджер панели.

## Состав

| Файл / папка | Что это | Переносить? |
|---|---|---|
| `database.json` | **База пользователей**; на Bothost: `/app/data/database.json` | ✅ обязательно |
| `secret.key` | Ключ подписи сессий — чтобы после переезда пользователи не разлогинились | ✅ обязательно |
| `backups/` | Автоматические резервные копии базы (создаются раз в 12 ч и при остановке сервера) | ✅ желательно |
| `users.js` | Клиентский слой данных (работает и с сервером, и без него) | ✅ часть проекта |
| `store.js` | Серверный движок базы (атомарная запись, бэкапы) | ✅ часть проекта |
| `.corrupt-*` | Повреждённые версии базы (создаются автоматически для разбора) | ⛔ можно удалить |

> ⚠️ В `database.json` лежат **хэши паролей**, а не сами пароли — это безопасно,
> но файл всё равно не стоит выкладывать в открытый доступ. Сервер (`server.js`)
> **запрещает** отдачу `database.json`, `secret.key` и `backups/` по HTTP.

## Как это работает

```
Браузер ──► Data/users.js (CollegeDB)  ──► API server.js ──► Data/store.js ──► Data/database.json
                │
                └─ если сервера нет (статика / file://) ──► localStorage браузера
```

- **Запущен `node server.js`** → CollegeDB работает через REST API, база **общая
  для всех** и хранится в `Data/database.json`.
- **Сайт открыт статически** → CollegeDB автоматически переключается на
  localStorage (данные только этого браузера). Режим определяется сам при
  загрузке страницы.

## Перенос на новый хостинг

1. Остановите сервер (`Ctrl+C` — при этом база сохранится и создастся бэкап).
2. Скопируйте **весь проект**, включая папку `Data/`.
3. На новом хостинге выполните `npm start` (или `node server.js`).

Готово — все пользователи, сессии и бэкапы на месте.

## Полезное

- Автоматический бэкап: раз в 12 часов + при каждом выключении сервера.
- Ручной бэкап: скопируйте `database.json` в `backups/`.
- Демо-аккаунт после первого запуска: **demo / demo123**.

## Роли пользователей

Роль хранится в поле `role` записи пользователя: `student` (по умолчанию при
регистрации) или `dev` (разработчик с доступом к «Панели управления»).

**Первого разработчика** назначить может только тот, кто имеет доступ к серверу:

```bash
node server.js --promote demo      # назначить разработчиком
node server.js --demote demo       # вернуть роль студента
node server.js --roles             # список всех пользователей и ролей
```

Либо бутстрап через переменные окружения хостинга (аккаунт создастся при
следующем запуске, затем переменные можно удалить):

```
ADMIN_LOGIN=boss
ADMIN_PASSWORD=секрет
ADMIN_FIO=Главный Администратор
```

**Дальше** роли переключаются без консоли: в интерфейсе «Панель управления»
клик по бейджу роли рядом с пользователем меняет её мгновенно (свою роль
менять нельзя).

## Переменные окружения сервера

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `HOST` | `0.0.0.0` | Адрес привязки |
| `COLLEGE_SECRET` | ключ из `secret.key` | Свой ключ подписи сессий (для продакшена) |
| `FORCE_SECURE` | — | `1` = добавлять `Secure` к cookie (только HTTPS) |
| `BACKUP_EVERY_MS` | `43200000` | Интервал автобэкапа (мс) |
| `BACKUPS_KEEP` | `20` | Сколько копий хранить |
